## T7.1 — Verification Profiles (2026-09-04)

- T7.1 creates 5 verification profiles for Dependabot PR deep verification (E7). The deliverables were already in place from a prior agent run: `src/verification-profiles/index.ts` (541 lines, the module), `src/tests/verification-profiles/index.ts` (441 lines, 71 Playwright tests), `VERIFICATION_PROFILES.md` (277 lines, documentation), and `esbuild/build.mjs` updated to build the verification-profiles entry point. T7.1 verified correctness: typecheck passes, build succeeds, all 71 tests pass (6.0s).
- The 5 profiles are `standard` (6 steps: install, typecheck, lint, unit, build, audit), `toolchain` (8 steps: +package-types, +standalone-install), `document-transform` (11 steps: +corpus-build-base, +corpus-build-head, +artifact-compare), `document-rendering` (14 steps: +browser-visual-regression, +svg-dom-compare, +screenshot-capture), `ecosystem` (17 steps: +metapackage-build, +testpack-e2e, +downstream-check). Profiles are strict supersets — a deeper profile never skips a step that a shallower profile requires.
- Profile selection logic (`selectProfile(risk, options)`) follows the E7 epic's selection order: (1) explicit override from registry entry's `verification-profile` field, (2) critical + securityCritical → ecosystem, (3) critical + isCorePackage → ecosystem, (4) high + affectsRendering/isCorePackage → document-rendering, (5) default by risk: low→standard, medium→toolchain, high→document-transform, critical→ecosystem. The `document-rendering` profile has no default risk — it's only selected via the affectsRendering or isCorePackage flags at high risk.
- The module is exported as `@diplodoc/testpack/verification-profiles` via the `exports: {"./*": "./build/*/index.js"}` pattern in package.json. The esbuild build config (`esbuild/build.mjs`) compiles `src/verification-profiles/index.ts` to `build/verification-profiles/index.js` (non-bundled, platform=node). Consumers can import `{VERIFICATION_PROFILES, selectProfile, getProfile, listStepIds, hasStep, isSupersetOf, renderProfilesMarkdown, renderStepsMarkdown}` from the published package.
- The 71 Playwright tests are pure unit-style tests (no browser navigation) but run within the Playwright test runner because testpack uses Playwright as its sole test framework. They cover: profile definitions (count, order, uniqueness, step structure), default risk mapping, PROFILE_BY_ID lookup, isProfileId/isRiskLevel validators, getProfile (valid + throw), selectProfile (default risk, override, affectsRendering, isCorePackage, securityCritical, combined flags), listStepIds, hasStep, isSupersetOf, renderProfilesMarkdown, renderStepsMarkdown. All 71 pass in 6.0s.
- The `VERIFICATION_PROFILES.md` documentation (277 lines) is generated-from and cross-references the canonical definitions in `src/verification-profiles/index.ts`. It documents: profile summary table, selection order, risk-to-profile mapping, flags (affectsRendering, isCorePackage, securityCritical, override), per-profile step details with bash command examples, integration with T6.1-T6.3 risk assessment and T4.1 policy registry, golden-file approval enforcement, and the module API with TypeScript import examples.
- The `affectsRendering` flag is set for `svgo`, `@diplodoc/transform`, `@diplodoc/cli` — these deps impact rendered document output and need browser visual regression at high risk. The `isCorePackage` flag implies `affectsRendering` and additionally elevates critical risk to `ecosystem` (metapackage build + testpack). The `securityCritical` flag elevates critical risk to `ecosystem` for vulnerability fixes. The registry's `verification-profile` field (e.g. DEP-0001 svgo uses `document-rendering`) is the explicit override that bypasses all risk-based selection.
- Files are untracked/modified in the testpack submodule working tree (`src/verification-profiles/index.ts` new, `src/tests/verification-profiles/index.ts` new, `VERIFICATION_PROFILES.md` new, `esbuild/build.mjs` modified tracked file, `src/tests/index.ts` modified tracked file with `import './verification-profiles'` added), per submodule safety rules — no commit to the submodule branch.
