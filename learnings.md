## T7.3 — Golden File Comparison (2026-09-04)

- T7.3 implements golden-file comparison for the `document-rendering` verification profile (T7.1). Three scripts, a Playwright test suite, and a CI workflow were already partially in place from a prior agent run. This iteration registered the test suite in `src/tests/index.ts`, fixed a whitespace normalization bug, created the CI workflow, and verified all 44 tests pass.
- **Three scripts** (all untracked in testpack submodule working tree, plain Node.js CJS — not compiled by esbuild since they're loaded via `require()` at runtime from the test files):
  - `scripts/build-corpus.js` (201 lines) — builds the reference document corpus at a git ref: resolves SHA, stashes uncommitted changes, checks out the ref, runs `npm ci` + `npm run docs`, copies `docs/output/` to the target dir, writes `metadata.json`, restores original working tree. Exports 9 pure helpers for testing.
  - `scripts/compare-artifacts.js` (354 lines) — compares file tree + normalized HTML + asset links between expected (base SHA) and actual (PR head SHA) corpus builds. `normalizeHtml` collapses whitespace, sorts attributes alphabetically, strips script content, normalizes style whitespace. `diffFileTree` detects added/removed/common files. `compareArtifacts` orchestrates all comparisons and returns `hasDifferences`. `renderReport` produces a markdown report with a "CODEOWNER Approval Required" section.
  - `scripts/compare-svg-dom.js` (432 lines) — compares SVG DOM structure: viewBox, element count/tags/attrs, gradient count, mask count, link count. Uses a lightweight string-based parser (`extractSvgStructure`) that extracts critical attributes (`id`, `href`, `viewBox`, `mask`, `fill`, gradient/filter/pattern/clip-path attrs) without requiring a full DOM parser. Tracks 29 critical SVG element types. `compareSvgDoms` orchestrates per-file comparison. `renderReport` includes CODEOWNER notice.
- **Whitespace normalization bug fix**: The original `normalizeHtml` used `.replace(/>\s+</g, '><')` which only strips whitespace BETWEEN tags (e.g. `<div> <p>` → `<div><p>`). But whitespace between a tag and text content (e.g. `<p> hello world </p>`) was NOT stripped — the regex only matches `>` followed by whitespace followed by `<`, so `<p> hello` has `> h` (not `> <`). Fix: replaced with two separate replaces `.replace(/>\s+/g, '>')` and `.replace(/\s+</g, '<')` which strip whitespace adjacent to tags from both sides, handling both inter-tag and tag-to-text whitespace. This makes `<div>\n  <p>  hello  world  </p>\n</div>` normalize to `<div><p>hello world</p></div>`.
- **Test suite** (`src/tests/golden-files/index.ts`, 469 lines, 44 tests): The test suite tests the pure helpers from all three scripts via `require()` (since the scripts are plain CJS JS files, not TypeScript). It does NOT require a running browser — the tests are pure unit tests that run within the Playwright runner. 5 integration tests require `docs/output/` to exist (skipped if not built). 3 CLI execution tests run the scripts as child processes via `execSync` and verify exit codes. 3 verification-profile integration tests verify the `document-rendering` profile references `corpus-build-base`, `corpus-build-head`, `artifact-compare`, `svg-dom-compare`, and `screenshot-capture` steps.
- **CI workflow** (`.github/workflows/golden-file-comparison.yml`, untracked): Triggers on `pull_request` with paths filter for `package.json`, `package-lock.json`, `docs/input/**`, `src/**`, `scripts/**`. Uses `runs-on: ubuntu-24.04` with `container: node:24-bookworm-slim` for a pinned Linux image (Node 24 + Debian Bookworm slim). Resolves base/head SHAs, builds corpus at both refs, runs artifact comparison and SVG DOM comparison (both with `continue-on-error: true` to capture all diffs), captures screenshots with `--trace on`, uploads all artifacts (expected/actual/diff.md/svg-diff.md/playwright-output/playwright-report) with 30-day retention, posts a PR comment with the diff report + CODEOWNER notice when differences are detected, adds a `golden-file-change` label, and fails the job if any differences are found. The `actions/upload-artifact@v4` step uses `if: always()` so artifacts are uploaded even when comparison steps fail.
- **CODEOWNER enforcement**: Three mechanisms: (1) both `renderReport` functions include a "CODEOWNER Approval Required" markdown section, (2) the CI workflow posts a PR comment with the diff report + explicit CODEOWNER notice, (3) the CI workflow adds a `golden-file-change` label to the PR. The verification profile steps `artifact-compare` and `svg-dom-compare` are `required: true`, meaning a failing comparison blocks the profile from passing. Dependabot cannot update snapshots independently — a human CODEOWNER must review and approve any golden-file change.
- **Pinned Linux image**: The CI workflow uses `node:24-bookworm-slim` container on `ubuntu-24.04` runner. Both base and head corpus builds run in the same container with the same Node.js, browser (`chromium` via `npx playwright install --with-deps`), and fonts, ensuring screenshot and HTML comparisons are reproducible (differences come from code changes, not environment drift). The `PLAYWRIGHT_BROWSERS_PATH: /ms-playwright` env var ensures consistent browser installation path.
- **Verification profile integration**: The `document-rendering` profile (T7.1) already references all golden-file comparison steps: `corpus-build-base`, `corpus-build-head`, `artifact-compare`, `svg-dom-compare`, `screenshot-capture`. The `ecosystem` profile extends `document-rendering` and inherits all these steps. The T7.3 tests verify these step IDs exist in the profile via `hasStep('document-rendering', 'svg-dom-compare')` and `hasStep('document-rendering', 'screenshot-capture')`.
