# `@diplodoc/testpack` — Architecture Analysis (T2.1)

> Source: `devops/testpack/` (git submodule: `github.com/diplodoc-platform/testpack`, published as npm package `@diplodoc/testpack`).
> Generated by reading the source tree: `src/`, `tests/`, `docs/`, `esbuild/`, `scripts/`, `playwright.config.ts`, `package.json`, `tsconfig.json`, `TESTS.md`, `README.md`, `AGENTS.md`.

## 1. Purpose

`@diplodoc/testpack` is a collection of **end-to-end (E2E) tests** for the Diplodoc documentation platform. It provides:

- Reusable **Playwright** test suites covering the user-facing rendering behaviour of Diplodoc components (terms, tabs, cut blocks, search, Mermaid diagrams).
- A reusable **Playwright configuration** factory with sensible defaults (retries, workers, reporters, screenshot strictness).
- A built-in **Express test server** that serves the generated HTML documentation so the browser-driven tests have something to navigate to.
- A **fixture documentation project** (`docs/input/`) that is built by `@diplodoc/cli` into static HTML (`docs/output/`) and served by the test server.

The package is consumed in two modes:

1. **Metapackage / workspace mode** — `devops/testpack/` is linked via npm workspaces; other Diplodoc packages can `import '@diplodoc/testpack/tests'` and `import config from '@diplodoc/testpack/config'` to reuse the suites and configuration.
2. **Standalone npm package mode** — installed via `npm install @diplodoc/testpack`; has its own `node_modules` and `package-lock.json`. The build artifact (`build/`) and the `docs/` fixture set are published to npm.

It is the canonical reference for how Diplodoc features are expected to behave, and is a critical input for the deep-verification epic (E7) and the per-package test epic (E3).

## 2. Architecture

### 2.1 High-level flow

```
docs/input/*.md (YFM fixtures)
        │  npm run docs   (@diplodoc/cli build -i docs/input -o docs/output)
        ▼
docs/output/*.html (generated static site)
        │  npm run serve / npm run start
        ▼
Express static server (src/server)  ──►  http://localhost:3000
        │  playwright.config.ts webServer
        ▼
Playwright test runner  ──►  chromium  ──►  src/tests/*  (assertions + screenshots)
```

The Playwright `webServer` hook wires this together automatically:

```typescript
// playwright.config.ts
webServer: {
  command: 'npm run docs && npm run start',
  url: 'http://localhost:3000',
  reuseExistingServer: !process.env.CI,
}
```

So a single `npm test`:
1. Builds the fixture docs (`npm run docs`).
2. Builds the server bundle + starts it (`npm run start` → `npm run build && npm run serve`).
3. Waits for `http://localhost:3000` to respond.
4. Runs all Playwright suites from `tests/docs.spec.ts` → `src/tests/index.ts`.

### 2.3 Key components

#### `src/config/index.ts` — configuration factory

Exports a function that accepts `additionals` and returns a full Playwright `defineConfig` with defaults:

- `testDir: './tests'`, `outputDir: '.playwright/result'`
- `updateSnapshots: 'missing'`
- `snapshotPathTemplate` → `tests/__screenshots__/{testFilePath}/{projectName}/{arg}{ext}`
- `forbidOnly: true`
- `retries: process.env.CI ? 2 : 0`
- `workers: process.env.CI ? 1 : 4`
- `fullyParallel: true`
- `expect.toHaveScreenshot.maxDiffPixels: 0` (strict visual regression)
- `use`: `baseURL` from `BASE_URL` env (default `https://hostmachine`), `ignoreHTTPSErrors`, `trace: 'on-first-retry'`
- `reporter`: HTML (`.playwright/html`) + JSON (`.playwright/json/results.json`), concat with caller-supplied reporters
- Caller-supplied keys override defaults; `expect` and `use` are deep-merged.

This is the mechanism by which other packages reuse testpack's configuration: `import config from '@diplodoc/testpack/config'; export default config({...})`.

#### `src/server/index.ts` — Express test server

A minimal Express app that serves static files from `PROJECT` (default `docs/output`) on `PORT` (default 3000):

- `/` → plain "Welcome" text.
- Middleware rewrites URLs: trailing-slash → `index.html`; no extension → `.html` appended.
- `express.static(PROJECT)` serves the rest.

Built **bundled** by esbuild (`bundle: true, packages: 'external'`) into `build/server/index.js` so it can run standalone without `node_modules` resolution of express.

#### `src/tests/index.ts` — suite barrel

Imports all suites in order: terms, tabs, cut, search, mermaid. This is what `tests/docs.spec.ts` pulls in (`import '../src/tests';`), and what external consumers get from `@diplodoc/testpack/tests`.

#### `tests/docs.spec.ts` — entry point

A single-line file: `import '../src/tests';`. Playwright discovers it via `testDir: './tests'`. This indirection lets external projects `import '@diplodoc/testpack/tests'` to reuse the whole suite set.

#### `scripts/init.js` — pre-test bootstrap

Runs before `npx playwright test` (see `package.json` `test` script). It:

- Locates the platform-specific Playwright browser cache.
- Installs `chromium` (with deps) via `npx playwright install --with-deps chromium` only if missing.
- Installs `@diplodoc/cli` (latest, `--no-save`) if not resolvable, so `npm run docs` can build the fixtures even when the CLI isn't a declared dependency (it's a `peerDependency`).

## 3. Test Framework

- **Framework:** [Playwright](https://playwright.dev/) (`@playwright/test`, `^1.60.0`).
- **Browser project:** `chromium` (configured in `playwright.config.ts` via `devices['Desktop Chrome']`). The `mermaid` suite additionally launches a raw `webkit` browser for a Safari check (currently `test.skip()` at the describe level).
- **Assertions:** Playwright built-in `expect` (visibility, attributes, classes, CSS, screenshots, viewport, focus, URL).
- **Visual regression:** `expect(locator).toHaveScreenshot()` with `maxDiffPixels: 0` (strict). Baselines stored in `tests/__screenshots__/docs.spec.ts/chromium/`.
- **Test discovery:** `testDir: './tests'`; the single `docs.spec.ts` re-exports all suites from `src/tests/`.
- **Reporting:** HTML + JSON reporters into `.playwright/`.
- **Guidelines:** `TESTS.md` is the authoritative manual — AAA pattern, full-structure assertions over partial checks, explicit IDs/selectors (avoid positional), wait for states not timeouts, helper functions for element groups.

## 4. Fixture Structure

Fixtures are **YFM (Yandex Flavored Markdown)** documents consumed by `@diplodoc/cli` to produce the static site under test.

### 4.1 Layout

```
docs/input/
├── .yfm                 # YFM project config: allowHtml, langs=['ru','en'], search=true
└── ru/                  # Russian-language fixture content (the only populated lang)
    ├── toc.yaml         # navigation: logo, header (Relative/Absolute/Dropdown links, right controls), items: Syntax{Tabs,Cut,Terms}, Search{Обзор,Статья1-3}, Mermaid
    ├── assets/          # diplodoc-dark.jpg, diplodoc-light.jpg (logo icons)
    ├── syntax/
    │   ├── tabs.md      # 157 lines — regular/grouped/radio/dropdown/accordion/nested/height-demo tabs
    │   ├── cut.md       # 159 lines — basic/html/code/nested/formatted/empty/list/grouped/open/height cuts (with stable element IDs)
    │   └── terms.md     # 14 lines — term definitions & usage
    ├── search/
    │   ├── index.md     # 12 lines
    │   └── article-{1,2,3}.md  # 5 lines each (content used by the search suggest tests)
    └── mermaid/
        └── index.md     # 17 lines — Mermaid diagram fixture
```

### 4.2 Conventions

- Each feature suite has a **dedicated fixture file** under `docs/input/ru/syntax/` (or `search/`, `mermaid/`) that exercises every scenario the corresponding Playwright suite asserts against.
- Fixtures use **stable element IDs** (e.g. `id="basic-cut"`, `id="group-cut-1"`, `data-diplodoc-group="height_demo"`, `data-diplodoc-variant="radio|dropdown|accordion"`) so tests can locate elements by explicit ID rather than positional selectors — as mandated by `TESTS.md`.
- `docs/input/.yfm` enables `search: true` and `allowHtml: true`; `langs: ['ru','en']` — only `ru` content is present.
- `docs/output/` is a build artefact (gitignored) and is **not** checked in as fixture input; it is regenerated by `npm run docs` and includes `_bundle/`, `_search/`, per-page `.html`, and `toc.js`.

### 4.3 Adding new fixtures / suites

1. Create a fixture markdown file under `docs/input/ru/<category>/feature.md` (or extend an existing one) using stable IDs/selectors.
2. Register it in `docs/input/ru/toc.yaml` under the appropriate `items` group.
3. Create the test suite directory `src/tests/<feature>/index.ts` (add `utils.ts` for helpers if needed).
4. Import the new suite in `src/tests/index.ts`.
5. Run `npm test -- --ui` to validate; update screenshot baselines with `--update-snapshots` if visual output changed intentionally.
6. Update `TESTS.md` if new patterns are introduced.

## 5. Entry Points

| Purpose | Entry | Notes |
|---------|-------|-------|
| Local test run | `playwright.config.ts` | Uses `src/config`, adds chromium project + `webServer`. Run via `npm test` (= `node ./scripts/init.js && npx playwright test`). |
| Build docs fixtures | `npm run docs` | `npx @diplodoc/cli build -i docs/input -o docs/output`. |
| Build package | `npm run build` | `node ./esbuild/build.mjs` → `build/{config,server,tests}`. |
| Serve docs | `npm run start` / `npm run serve` | `npm run build && node build/server`. |
| Reusable config | `@diplodoc/testpack/config` → `build/config/index.js` (from `src/config/index.ts`) | `export default config({...})`. |
| Reusable suites | `@diplodoc/testpack/tests` → `build/tests/**/*.js` (from `src/tests/**`) | Imported by `tests/docs.spec.ts`. |
| Reusable server | `@diplodoc/testpack/server` → `build/server/index.js` (from `src/server/index.ts`, bundled) | Standalone-runnable. |

`package.json` `exports` map: `"./*": "./build/*/index.js"` — so `@diplodoc/testpack/config`, `@diplodoc/testpack/server`, `@diplodoc/testpack/tests` resolve to the corresponding `build/<name>/index.js`. Published `files`: `["build", "docs"]`.

## 8. Integration with the Metapackage

- Located at `devops/testpack/` and declared as a workspace package of the Diplodoc metapackage root `package.json`.
- It is a **git submodule** (`.git` file, not a directory) pointing at `github.com/diplodoc-platform/testpack`; the metapackage pins it by commit SHA.
- Dependencies are resolved from the metapackage root `node_modules` in workspace mode; the local `package-lock.json` is regenerated with `npm i --no-workspaces --package-lock-only --ignore-scripts` for standalone compatibility.
- `@diplodoc/cli` (peer dependency, `^5.53.0`) is provided by the metapackage workspace in workspace mode and auto-installed via `scripts/init.js` in standalone mode.
- `@diplodoc/infra` (devDependency `2.2.3`) supplies `tsconfig.json` base and the `lint` script toolchain.
- Other packages consume testpack via `import '@diplodoc/testpack/tests'` and `import config from '@diplodoc/testpack/config'`.

## 9. Observations Relevant to E2/E3/E7

- The suite is **feature-driven** (terms/tabs/cut/search/mermaid), not package-driven. E3 ("Package Tests", 28 tasks) will need a strategy to map per-package behaviour onto either new fixture files + new suites here, or separate per-package Playwright projects that reuse the `config` factory.
- The **Mermaid suite is currently fully skipped** (`test.skip()` at the describe root). E3's `T3.20 Tests mermaid` should re-enable it.
- The **Search suite navigates from `./ru/syntax/cut`** as its `beforeEach` base page (it uses the header search input present on every page).
- Fixtures intentionally use **stable, semantic IDs/selectors** — any new package tests must follow the same convention (see `TESTS.md`).
- `scripts/init.js` makes the package self-bootstrapping (installs chromium + CLI if missing), which matters for CI images that do not pre-install them.
- Strict screenshot regression (`maxDiffPixels: 0`) means intentional UI changes require `--update-snapshots`; baseline PNGs live in `tests/__screenshots__/`.
- The build pipeline emits **non-bundled** `tests` and `config` (external packages) but a **bundled** `server` — relevant when packaging for npm distribution.
